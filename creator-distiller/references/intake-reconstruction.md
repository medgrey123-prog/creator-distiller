# 采集层重建：四路合流

公开作品通常更容易展示结论，未必包含作者向客户提问、核实约束或随数据调整的过程。仅在需要实际应用且材料不足时，按下列路径补充；不要把推导结果归属为作者亲述。

1. **概念倒推**：对每个概念问“要使用或验证这个判断，必须知道用户什么？”例如，“先验证再扩大投入”需要知道验证指标、可承担成本和观察周期。它帮助找到重要问题，但不保证完整。
2. **决定倒推**：先列最终要做的决定，再列必须输入。以内容项目为例：定位需要经验与受众；形式需要出镜意愿与设备；频率需要产能；商业目标需要产品与交付能力。换行业时重写决定清单，不沿用内容运营默认项。
3. **实录挖掘**：若有合法可用的答疑、诊断或访谈实录，提取作者真实问过的问题及追问触发条件，保留出处。实录与推导分别标记。
4. **实际问答迭代**：围绕当前决定询问关键缺口，在方案使用过程中记录“缺哪条信息会改变这条建议”，逐步完善采集清单；信息充分就推进，不固定轮次。

现场判断与数据经验只能通过实际运行继续检验，不宣称已完整复制。可用“待决定事项 / 必须输入 / 已知事实 / 缺口 / 信息来源 / 对结论的影响”记录结果。
