# 交付核验

## 1. 底库结构

有本地执行能力时运行（脚本与归档都用绝对路径）：

```text
python3 "<SKILL>/scripts/archive.py" validate "/abs/path/to/archive" --stage insights
```

`PASS WITH GAPS` 表示结构通过但有登记缺口，报告覆盖比例；用户要求全量时用 `--strict`，同时要求 `scope.status=complete`；范围证据仍需人工复核。

检查来源 ID 唯一、路径不越界、正文状态与存在性、bundle 对应当前输入、逐条总结的覆盖与指纹、三份知识文件存在、显式引用的格式及 ID。非零退出应修复，无法修复则报告部分完成及缺口。无执行能力时按相同项目核对，标明非脚本验证。

**此脚本不核验生成的能力包或实际服务能力**，不判断全部结论是否有引用、引用是否支持观点、详解是否完整，也不证明已取得某人所有历史资料。

## 2. 底库内容与细度

逐条核对详解覆盖表与原文实质段落；关键概念、数字、步骤、案例、条件和冲突回查具体定位。其他细节的复核可按风险安排并记录实际范围，未检查不能称全量复核。ASR 疑点保留，合理猜测不等于校对。

检查 C/M/E 编号、对应关系、依赖与详细正文链接；不以概览替代细节。表达模式检查共性与反例。概念、方法没有证据时写缺口，不为交付填满卡片。

分别报告请求范围、发现数、取得完整正文数、详解数、底库覆盖、原文回查范围、冲突与未解决问题。`scope.status=complete` 是采集者陈述，需看证据，未知/删除/私密资料不能忽略。

## 3. 选定能力包

对照 `request.md`：所选模式均有实际成品，未选模式不额外生成；只要知识库的例外有明确用户依据。

- 每包入口有正确 name/description、任务流程、按需读取知识的路径；无未填写的模板字段。
- 资料包括所需完整卡片、依赖概念、关键案例与反证，不只复制短摘要；来源、证据和版本可核查。
- 相对文件链接可解析。复制到另一个目录后能读取必要文件；未交付兄弟包、作者机器绝对路径和全局已安装技能不能成为隐藏依赖。
- service 包额外有角色、工作流程、启动文档及空白状态模板，实际用户数据放私人工作目录；仅有身份提示词不算完整交付。
- 原文/底库变化后标记受影响包，回查和重新试运行，不只修改日期或指纹。

机器能检查存在与路径；是否忠实、可用及在各平台运行仍需独立证据。无相应运行权限时写明“文件已交付，未安装/未启动”。

## 4. 实际任务与最终报告

按 [试运行记录](../templates/trial-report.md) 执行并保留输入和输出。修复证据暴露的问题；无任务或能力时明确待运行，不强制虚构样例来换取通过。

交付完整底库入口、每个所选包、安装/启动说明及状态，注明哪些验证真实执行、哪些仍未执行。服务包的新对话创建、状态恢复、后台调度分别报告，不能由其中一项推断其余均完成。PDF 仅按需转换并实际检查。
