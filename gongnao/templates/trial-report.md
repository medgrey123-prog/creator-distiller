# 试运行记录填写要求

每个所选包保存 `trial.md`。按实际执行情况填写，缺少输入时也保留待运行记录，不制造已通过的示例日志。

- 包名称、模式、版本/底库版本、日期、执行环境。
- 状态：待运行 / 样例运行 / 用户任务运行 / 失败待修；用户验收单独记录“未请求/待反馈/已确认”。
- 输入：实际问题、给定事实、限制；注明是真实用户任务还是合成样例。
- 已执行动作与输出：保留可查看的产物路径或输出正文；未运行不能填预期输出为实际结果。
- 依据：实际读了哪些知识文件、卡片和来源；哪些判断是新推导。
- 检查：是否达到任务目标、事实与边界是否保持、包外依赖是否可用；失败证据及修复后复测结果。
- 剩余缺口和最小下一步。

思考型检查迁移和不适用条件；表达型检查用户事实与结构迁移；服务型检查角色范围、背景问询、具体交付和状态衔接。文件格式检查、样例测试、真实运行和用户验收四者不能互相替代。没有足够素材，不用假任务冒充真实业务测试。
