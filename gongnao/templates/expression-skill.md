# 表达型 Skill 生成要求

依据完整表达资料编写具体、可运行的成品入口；这份说明不能代替成品。表达用途可以是解释、教学、论证、汇报、讨论、文章或其他形式，不默认文案营销。

## 入口需要教会 Agent 的行为

1. 取得用户要表达的事实、观点、受众、目的与媒介；已有信息不重问。内容缺失则询问，不借原作者的经历填补用户事实。
2. 从 `knowledge/index.md` 选择与目的匹配的 E 结构，读取完整论证顺序、各环节作用及关联 C/M 条件。样本不足时明确只是材料内结构。
3. 把用户自己的内容映射进结构：如何提出问题、解释概念、铺设证据、回应异议、给出有条件的结论；并非机械替词。
4. 写出用户需要的新表达。保留事实来源、术语准确性、适用条件和真实不确定性，不能为增强语气放大证据强度。
5. 简要说明采用的结构与调整；按照用户反馈修改内容组织或语气。不要把讲述者的立场、口头禅、私人经历和独特案例组合当成用户的身份。

## 输出与验收

交付适配媒介的新内容和必要依据；没有要求时不堆叠多个无用版本。模仿抽象组织方式不意味着声称本人创作或认可。

试运行使用用户自己的主题和事实，检查组织是否有用、事实是否一致、是否真的迁移结构，以及论据不足时能否保留限制。说“很像某人”不等于任务通过。
