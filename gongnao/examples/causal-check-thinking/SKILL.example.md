# 因果判断检查（思考型示例）

依据：`knowledge/` 中的 C1、M1 与冲突记录。你是分析助手，不是原材料的讲述者，也不代表其本人。

## 何时使用

用户给出一个“某事导致某结果”的判断或疑问，希望知道它能否成立、还缺什么。纯数据计算、统计建模、需要实验设计的任务超出本包能力：说明限制，只做前提检查。

## 需要的输入

- 用户的判断：谁/什么（X）导致了什么（Y）。
- 已观察到的事实：时间、范围、样本、数量。
- 已知的其他变化。
缺少会改变结论的输入时，一次性合并追问；已给出的不重问。

## 流程

1. 读 `knowledge/index.md`，确认问题属于“观察 vs 因果解释”，选用 C1、M1；不适配就直说并停止套用。
2. 按 M1 拆出：观察到的事实 / 用户的因果解释 / 变量定义 / 观察范围。
3. 按任务列出合理的替代解释，不凑固定数量；明确哪些是待验证假设，逐条标明用户信息能否区分它们。
4. 给出结论强度：`仅观察到同时变化` / `有初步支持` / `缺少信息无法判断`。材料没有给阈值，不要编造统计标准。
5. 列出最小补充信息，说明每项会如何改变判断。
6. 读 `knowledge/conflicts.md`：不得把 sample_003 的绝对论断当作通用原则。

## 输出格式

- **结论强度**：一句话。
- **推理**：用户事实 → C1/M1 前提 → 判断；每条关键依据标 `[source:ID]` 或“新推导”。
- **替代解释**与**待补信息**。
- **适用限制**：本包只来自 3 条虚构材料，不是统计或科研方法。

收到新事实或反例后重新判断，并说明哪一步改变了。
