# 从完整底库生成可用能力包

完成详细底库后，依据 `request.md` 的选项组装。无需用户另装一个“转换系统”；共脑自身负责这一步。资料不足时保留草稿与缺口，不伪造成熟能力。

## 交付结构与选择

```text
archive/
  request.md
  sources.json / raw/ / bundles/ / summaries/ / insights/
  00_index.md / all_summaries.md
  deliverables/
    subject-thinking/    仅选择 thinking 时生成
    subject-expression/  仅选择 expression 时生成
    subject-service/     仅选择 service 时生成
  delivery.md            选择、包路径、范围、验证与启动状态
```

完整的成品参考见 [causal-check-thinking 示例](../examples/causal-check-thinking/README.md)（示例入口名为 `SKILL.example.md`，真实包必须命名为 `SKILL.md`）。

`subject` 替换为安全且可辨识的小写英文/数字连字符标识；显示名称可用中文。每包 `SKILL.md` 的 YAML `name` 与文件夹一致，少于 64 字符，description 说明何时使用和实际能力，不能只写“像某某一样”。不把模板占位符交成成品。

每个独立包包含：

- `SKILL.md`：触发范围、所需输入、操作与判断流程、知识读取路径、预期输出、缺口处理。
- `knowledge/index.md`：问题/能力 → 详细卡片/文件的相对路径与适用条件。
- `knowledge/` 中的相关完整卡片、方法、表达结构、案例、反证和依赖说明；不要只复制几句概括。
- `knowledge/sources.md`：包内实际引用的 ID → 标题、作者、日期、原始地址/原归档相对位置、具体定位、正文及校对状态；本地源路径不作为唯一证据。
- `knowledge/evidence/`：在用户权限范围内保存支撑关键判断的必要证据片段或可携带原文，使离开主归档后仍能核对。不需要复制全部原始资料；不获许可不能公开传播，无法携带时明确外部依赖和验证限制。
- `knowledge/provenance.md`：底库版本/生成时间、输入文件及 SHA-256（有工具时）、所用 C/M/E 与来源范围、人工归纳/推导标记、缺口；无法计算指纹写未计算，不伪造。
- `trial.md`：实际试运行或待试运行记录，见 [试运行模板](../templates/trial-report.md)。

需要更新生成包时先保护用户在包内的改动，使用新目录或合并并保留变更说明。将整个文件夹移动到另一个临时位置，再核对链接和知识读取，避免工作机绝对路径、遗漏依赖、软链接或越界引用造成假便携。

## 三种能力如何取资料

| 类型 | 主资料 | 必要关联 | 使用结果 |
|---|---|---|---|
| thinking | 概念、前提、判断及方法 | 案例、反例、冲突、来源 | 用户问题的推理、可选解释/行动与适用限制 |
| expression | 表达与论证结构 | 对应概念、论据、案例作用、条件 | 基于用户自己事实和目标的新表达及组织理由 |
| service | 服务范围内的概念、方法、表达 | 用户信息需求、证据边界、服务流程 | 持续问询、分析、交付、跟进与调整 |

只有 service 时也须自带服务所需资料和操作流程，不强制依赖另外两个已安装 Skill。全选时三包各自可用；适量复制相关知识是可移植快照，不重复建设主底库。多个包的知识快照应标明同一底库版本，更新时报告哪些包受影响。

以后补做表达型时，先读主底库的表达资料和原文，不用思考型入口“猜出”讲述者风格。若主底库遗失且现有包缺资料，明确需补材料，不能凭空还原。

## 成品要求

入口指令必须能指导 Agent：识别用户任务 → 读取必要知识 → 检查适配/缺口 → 执行 → 解释依据与限制 → 接收修正。不能仅写角色口号或复制整篇知识文档。

共脑负责生成可安装的目录和使用说明，不自动安装到所有平台或新建聊天。按用户明确指定的平台适配；不支持 Skill 的环境可读取入口与资料作为启动材料。没有文件工具时按路径分段输出可保存的内容，说明“文本交付，未写入/未安装”。

使用 MIT 模板不代表获得原作者素材授权。私有用户记录与原始资料不要混入公开发布包，发布是单独授权的动作。
