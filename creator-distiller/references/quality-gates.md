# 交付核验

## 结构检查

有本地执行能力时运行 `python scripts/archive.py validate <archive> --stage distilled`（以 skill 目录为当前目录；Python 命令依环境选用）。它会检查：

- 来源 ID 唯一、路径不越界、源清单非空；
- 每个来源正文完整状态与正文存在性；bundles 是否对应当前输入；
- 总结与来源一一对应、指纹是否对应当前 bundle、有无非清单文件；
- 三件套存在、显式 `[source:ID]` 引用格式和 ID 是否有效。

非零退出表示检查失败，应修复或以“部分完成”交付并列明具体缺口。脚本不判断全部文段是否都已引用，不判断引用是否支持观点，也不证明取得了平台所有历史资料。

没有执行工具时按同一清单逐项核对，标记为人工/模型核对，不宣称已运行脚本。

## 证据内容检查

关键概念、数字、方法步骤与冲突逐项回查原文定位；其他条目按风险与样本规模抽查，写明检查范围。避免用标题猜测含义、把原作者口径当客观定律。ASR 不确定术语保留疑点，合理猜测不等于校对。

检查概念/方法编号与交叉链接；没有方法对应时明确说明，不凑链接。表达模式需检查跨样本共性及反例；示范不复制独特表达或案例组合。

## 完整性分开报告

分别报告：请求范围、发现数、正文完整数、总结数、蒸馏覆盖范围、引用结构核验结果、原文回查范围、未解决问题。原始作品状态 partial/missing 的说明文件不算完整总结。

所有来源存在也不能自动判“全量”；`scope.status=complete` 是采集者陈述，必须看其范围和证据。未知、删除、私密、地区或登录限制需要明确说明。

## 交付

默认 Markdown 索引 + 总结 + 三件套 + 范围/缺口说明；按宿主支持提供可用文件链接，路径允许空格和中文。若要 PDF，检查实际输出的中文、分页与链接后再标记完成。不要将“生成成功”当作用户已验收。
